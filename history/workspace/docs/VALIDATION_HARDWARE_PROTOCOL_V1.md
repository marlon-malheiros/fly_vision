# Validation, mechanism checks and portable deployment — V1

Started 2026-10-21. New work under the active user goal to validate, improve and produce an implementation suitable for real hardware. Studies A/B and their acceptance criteria remain sealed. This protocol declares proposed scientific criteria before new response outcomes; the executable manifest will freeze methods after implementation/preflight and before the new study runs.

## Requirements and evidence

1. Preserve previous graph counts, frontend computation, gains and published evidence. Verify predecessor indexes and hash all new inputs, methods and receipts. Never overwrite sealed results.
2. Validate a causal, bounded-memory streaming implementation against the original Python frontend and original differential equations on independent artificial inputs and actual saved walking inputs. Source routing is fixed anatomy-derived wiring; intended speed/yaw may enter only the renderer and explicitly speed-conditioned evaluation, never the image processor.
3. Reassess numerical sensitivity at small yaw, including full retinal/frontend spatial sampling at panorama pitches 1, 0.5 and 0.25 degrees while keeping the retinal circuit's angular grid, neighbor displacement and pooling unchanged. Separately refine frontend/input/solver clocks. A direct-ray receptor comparison is a diagnostic, not a new physiological eye model. Include straight controls and identify decision changes. Do not call a threshold converged from a subset check.
4. Extend evaluation to independently seeded environments, with prospective training/calibration/test membership. Primary evaluation transfers the sealed Study A readouts unchanged. Secondary fits use only new training scenes, cutoffs use only new calibration scenes, and testing is isolated. Preserve all failures, raw predictions and confidence intervals. The inherited finite-scene detection rule remains at least 80% detection, 80% correct signs and at most 10% straight false alarms, sustained at larger tested yaw magnitudes. No added neural noise or favorable scene selection.
5. Disentangle bIPS lesion effects, decoder changes and expanded-graph normalization. Use identical visual drives across circuit copies. Keep expanded-intact and dual-new-family silence controls. Report response shifts and false alarms separately from loss of information; no biological-causality claim follows from a numerical lesion.
6. Audit accessible physiological data and exact stimulus, hemisphere/neurite identity and observation-model constraints. Quantitative physiological validation requires independent recordings under justified stimulus/measurement mappings. An unmatched rate-versus-calcium index remains a diagnostic. No invented gap conductances, baseline noise, reporter mapping or neural parameter adjustment for classification performance.
7. Supply a deployable streaming implementation, exportable model package, deterministic replay CLI and camera/retinal input contract. Measure memory and latency on the actual available CPU; test malformed input, clocks, reset and numerical identity. A 100-Hz neural-input stream has a 10-ms processing budget; report latency distributions, throughput, missed deadlines and the scope of camera/render timing. A sensor-rate change is a separately evaluated deployment configuration. CPU execution is hardware evidence; a robot/camera target without direct access remains unverified.
8. Improvements may address computational efficiency, portability and demonstrated implementation defects without changing biological parameters. Any new scientific circuit or observation assumption needs a separately identified version and evidence. No closed-loop motor commands in this validation study.

## Execution order and resources

Audit and independent preflight precede the outcome freeze. Then execute convergence comparisons, new-environment generalization, paired mechanism analysis and physiological benchmarks wherever evidence permits. Develop and benchmark the hardware path in parallel with these sequential scientific gates. Exact scene seeds, workload, intervention definitions, analysis criteria and code/library digests must be fixed in the prospective manifest before new neural outcomes. Resource changes may depend on measured runtime/storage, not favorable responses.

The available development machine is an Intel i5-12450H x86-64 CPU with approximately 15 GiB RAM. No video, USB serial or robot device was exposed in the initial inventory. Only approximately 6.3 GB filesystem space was free; use compact trajectories, reproducible source hashes/checkpoints and bounded temporary storage. Preserve old evidence, reserve at least 2 GB free disk, and do not start unbounded full-movie/full-state exports. Hardware target clarification is pending; portable Linux CPU is the provisional implementation target, not evidence of Raspberry Pi/Jetson or physical robot performance.

## Deliverables and completion boundary

Versioned source and meaningful tests; prospective configuration and manifest; numerical comparisons and decision-level convergence evidence; held-out generalization/ablation tables and figures; physiological evidence/constraint audit; portable package, runnable replay and measured performance; technical report and short undergraduate explanation. Save a dated progress snapshot before sealing any completed study. The live progress report stays outside immutable indexes. The active broad goal remains incomplete while a required validation or deployment claim lacks evidence; negative results must not be relabeled success.
